# Phase 2 · Step 5 — E2E

## Overview

- **Purpose**: Write the E2E plan, then test the complete user flow in the running application with real data.
- **Agent/Skill**: general-purpose agent
- **Model**: `balanced`
- **Gate**: `soft` — plan path, criteria passed out of total, failures fixed and re-run
- **Inputs**: the spec (acceptance criteria); `docs/architecture.md` (database, auth, external services); `docs/flows.md` (§4 cross-feature hand-offs); the running application, started fresh
- **Outputs**: `docs/E2E-TESTS.md`; test results
- **Template**: `kit/templates/e2e-tests.md`

## Scope

- **In**: every acceptance criterion; the complete user flow with real data; external-service provisioning requirements.
- **Out**: unit tests and mocked data.

## Rules

### Plan

- Copy `kit/templates/e2e-tests.md` to `docs/E2E-TESTS.md` and have the general-purpose agent fill every placeholder from the spec. One file serves the whole project: under `scope: feature`, the first feature creates it and each later feature adds its Feature block to Section 3, touching Sections 2, 4, and 5 only for new prerequisites. When a feature's spec changed after its Feature block exists (living spec or flow-back), edit that block in place: add, rename, or remove criterion rows to match the spec and reset their Status to blank so they re-run; do not append a second block.
- Every acceptance criterion ID appears as a row in Section 3; an intentionally excluded criterion appears with its reason. Section 4 is complete for every external service.
- Give the user the file path. If a prerequisite needs manual provisioning (for example Supabase test users — see the example in the template), ask the user to complete it and confirm. E2E cannot start while any Prerequisites Checklist item is unchecked.
- `docs/E2E-TESTS.md` is committed at Ship, so it stays secret-free like `docs/ENV_SETUP.md`: test account emails and passwords live in `.env` (git-ignored); the doc lists key names only.

### Run

- Run every criterion first and mark each PASS, FAIL, or BLOCKED (blocked by a prior failure, not an independent failure). Do not fix anything inline; fixes made mid-run let later criteria regress undetected.
- Walk the complete user flow as a real user would. Test each shared interaction pattern (modal, form validation, navigation) once, not once per criterion. `scope: all`: every interaction between two features (data created in one and used in another) has its own test case — the failure mode specific to a one-pass build; derive these cases from `docs/flows.md` §4 hand-offs, one case per row.
- After the full run, send all FAILs to the implementer in one dispatch.
- Before the re-run, have the Step 4 reviewer check the fix diff only. This applies to every fix made after Step 4, including fixes from Step 6.
- Re-run only the affected scope, determined by the files the fix touched: isolated to one feature's files → that feature's test cases; shared code (utilities, middleware, state, routing, DB schema) → every test case that depends on it. Do not re-run the full suite when the fix does not warrant it.
- Record results in the Status column of `docs/E2E-TESTS.md`.

## Completion Criteria

- [ ] `docs/E2E-TESTS.md` exists with every acceptance criterion mapped and every prerequisite checked
- [ ] Every criterion exercised against the fresh running application; none left FAIL or BLOCKED
- [ ] Fix diffs reviewed and affected scope re-run
- [ ] Summary presented to the user
