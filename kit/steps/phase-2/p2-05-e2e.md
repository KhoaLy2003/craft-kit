# Phase 2 · Step 5 — E2E

## Overview

- **Purpose**: Write the E2E plan, then test the complete user flow through the system's real interface (browser, API, CLI, or mobile) with real data.
- **Agent/Skill**: general-purpose agent
- **Model**: `balanced`
- **Gate**: `soft` — summary with counts and evidence path
- **Inputs**: the spec (acceptance criteria); `docs/architecture.md` (database, auth, external services); `docs/flows.md` (§4 cross-feature hand-offs); the running application, started fresh
- **Outputs**: `docs/E2E-TESTS.md` (Status column and Section 8 Run Log); run evidence in `docs/e2e-runs/<YYYY-MM-DD>[-rerun-N]/`
- **Template**: `kit/templates/e2e-tests.md`

## Scope

- **In**: every acceptance criterion; the complete user flow with real data; external-service provisioning requirements.
- **Out**: unit tests and mocked data.

## Rules

### Plan

1. Copy `kit/templates/e2e-tests.md` to `docs/E2E-TESTS.md` and fill every placeholder from the spec; the template comments give the cell formats. One file serves the project. Per row: the AC ID and a short label, never the criterion text. Take the `Command` from the E2E row of Verification Commands.
2. Work from this feature's block only:
   - New feature (`scope: feature`): add a block to Section 3; touch Sections 2, 4, and 5 only for new prerequisites.
   - Spec changed: edit the block in place and reset Status to blank; never append a second block.
   - Shipped earlier, now changed (its spec, or shared code that re-runs its cases): restore the block from `docs/archive/e2e/<feature-slug>.md`, edit it in place; Ship archives it again.
3. Every acceptance criterion ID is a Section 3 row; an intentionally excluded one carries its reason. Each applicable NFR with a testable target (an accessibility scan, a latency threshold) is a case with an `NFR-<category>-<n>` ID, run with the E2E command; a non-testable one is excluded with its reason. Section 4 covers every external service.
4. Give the user the file path. If a prerequisite needs manual provisioning (e.g. Supabase test users), ask the user to do it and confirm, then record the account in `.test-accounts.json` (`kit/guides/test-accounts.md`; reuse first). E2E cannot start with any Prerequisites Checklist item unchecked.

### Run

Start the app fresh. **Fix nothing inline**, or later criteria can regress undetected.

1. Sign in with every referenced account and update its `status` and `last_verified` in `.test-accounts.json`.
2. Run every criterion and mark PASS, FAIL, or BLOCKED (by a prior failure). Walk the complete flow through the real interface, as a real user or client (non-browser: real requests, commands, or device actions; no mocks). Test each shared interaction pattern (modal, form validation, navigation) once. `scope: all`: one case per `docs/flows.md` §4 hand-off row.
3. Save evidence in `docs/e2e-runs/<YYYY-MM-DD>[-rerun-N]/`: the runner's full output as `run.log` plus its own artifacts (HTML report, failure traces, screenshots, or video; non-browser: the request/response log). Configure the runner to keep failure artifacts, and make sure `docs/e2e-runs/` is git-ignored (add it if missing). Measured results and data notes go in the evidence folder. Record results in the Status and Evidence columns and append one Run Log row.
4. Send all FAILs to the implementer in one dispatch, each with its AC ID, observed result, and artifact path.
5. Check the fix diff before re-running (also for Step 6 fixes): over about 30 lines or touching auth, data access, or other security-sensitive code → dispatch the Step 4 reviewer; otherwise the orchestrator reads it and runs the Verification Commands.
6. Re-run only the affected scope: one feature's files → that feature's cases; shared code (utilities, middleware, state, routing, DB schema) → every dependent case. Repeat from 3 until none FAIL or BLOCKED.

**Dispatch failure.** Follow conventions rule 15. Running inline does not relax this step: the app is still started fresh and every case still runs; if that cannot be met, report it as a limit, never as a pass.

### Report

One summary led by the Gate line (`> **Gate:** ...`): PASS out of total for criteria and NFRs separately, the command, date and fresh-app confirmation, failures with their fix and re-run result, exclusions with reasons, and the evidence path (`scope: all`: plus per-feature counts and hand-offs). If the run cannot start or a failure survives the fix cycles, report what is missing or failing, the artifact path, and the decision needed. Never report a count without a run behind it.

## Completion Criteria

- [ ] `docs/E2E-TESTS.md` maps every acceptance criterion and testable NFR, with every prerequisite checked
- [ ] Every case run against the fresh app; none FAIL or BLOCKED; fix diffs reviewed and affected scope re-run
- [ ] Evidence saved per run under `docs/e2e-runs/`; one Run Log row per run in `docs/E2E-TESTS.md`
- [ ] Summary (counts, failures and fixes, exclusions, evidence path) presented to the user
