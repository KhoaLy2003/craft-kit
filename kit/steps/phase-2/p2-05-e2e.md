# Phase 2 · Step 5 — E2E

## Overview

- **Purpose**: Write the E2E plan, then test the complete user flow through the system's real interface (browser, API, CLI, or mobile) with real data.
- **Agent/Skill**: general-purpose agent
- **Model**: `balanced`
- **Gate**: `soft` — plan path, criteria passed out of total, failures fixed and re-run
- **Inputs**: the spec (acceptance criteria); `docs/architecture.md` (database, auth, external services); `docs/flows.md` (§4 cross-feature hand-offs); the running application, started fresh
- **Outputs**: `docs/E2E-TESTS.md`; test results
- **Template**: `kit/templates/e2e-tests.md`

## Scope

- **In**: every acceptance criterion; the complete user flow with real data; external-service provisioning requirements.
- **Out**: unit tests and mocked data.

## Rules

### Plan

- Copy `kit/templates/e2e-tests.md` to `docs/E2E-TESTS.md` and have the general-purpose agent fill every placeholder from the spec. Set the `Verification type` (browser, API, CLI, mobile, other) and take the `Command` from the E2E row of Verification Commands (a backend-only project records `API`, no browser). One file serves the project: under `scope: feature` each feature adds its block to Section 3, touching Sections 2, 4, and 5 only for new prerequisites. If a spec changed after its block exists, edit the block in place (add, rename, or remove rows; reset Status to blank); never append a second block.
- Every acceptance criterion ID appears as a row in Section 3; an intentionally excluded criterion appears with its reason. Section 4 is complete for every external service.
- Each applicable NFR with a testable target (e.g. an accessibility scan, a latency threshold) is a Section 3 case with an `NFR-<category>-<n>` ID, run with the E2E command; a non-testable one is excluded with its reason.
- Give the user the file path. If a prerequisite needs manual provisioning (e.g. Supabase test users), ask the user to do it and confirm, then record the account in `.test-accounts.json`. E2E cannot start with any Prerequisites Checklist item unchecked.
- `docs/E2E-TESTS.md` is committed, so it stays secret-free: accounts come from `.test-accounts.json` (conventions → Test account registry, reuse first); the doc lists account `id`s and roles only.

### Run

- Before running, sign in with every referenced account and update its `status` and `last_verified` in `.test-accounts.json`.
- Run every criterion first, marking PASS, FAIL, or BLOCKED (by a prior failure). Fix nothing inline, or later criteria can regress undetected.
- Walk the complete flow through the real interface, as a real user or client (non-browser: real requests, commands, or device actions, no mocks). Test each shared interaction pattern (modal, form validation, navigation) once. `scope: all`: every cross-feature interaction gets its own case, one per `docs/flows.md` §4 hand-off row.
- After the run, send all FAILs to the implementer in one dispatch.
- Before re-running, have the Step 4 reviewer check the fix diff only (also for fixes from Step 6).
- Re-run only the affected scope: one feature's files → that feature's cases; shared code (utilities, middleware, state, routing, DB schema) → every dependent case.
- Record results in the Status column of `docs/E2E-TESTS.md`.

## Completion Criteria

- [ ] `docs/E2E-TESTS.md` exists with every acceptance criterion mapped and every prerequisite checked
- [ ] Every criterion exercised against the fresh running application; none left FAIL or BLOCKED
- [ ] Every applicable NFR with a testable target has a test case and passed
- [ ] Fix diffs reviewed and affected scope re-run
- [ ] Summary presented to the user
