# Conventions — Detail

> **Agent-facing.** Read the section a rule in `kit/orchestrator-conventions.md` points to, only when you are about to act on that rule.

## Git hygiene (rule 9)

The `docs/backlog.html` entry is generated by `kit/scripts/render-backlog.js` and never committed; a project that already tracks it runs `git rm --cached docs/backlog.html` once. The HTML entry is not verified. Upgrade, bug-fix, admin and Phase 3 do not depend on Phase 1 Step 1 for this.

## Kit version record (rule 10)

Workflows that finish a one-time setup (Phase 1 closeout, Adopt closeout, Project Upgrade report) write `docs/.craft-kit.json` from `.craft-kit-version` in the installed kit directory. Preflights compare it with the installed version, warn on a mismatch, and never block. A preflight that writes (Phase 2) warns once and then records `acknowledged_version: <installed version>`; while it equals the installed version, preflights stay silent. A new install changes the version and re-arms the warning. Read-only routers (`START.md`) honor the field but never write it.

## Docs lint (rule 11)

Errors (invalid `Status`, malformed `Last updated`) are fixed before continuing. Warnings (`stale: <based-on file> was updated after <this file>`) are shown to the user and never block. After re-checking a file against a newer source, add `**Reviewed against:** <YYYY-MM-DD>` under its metadata header (no other change); the warning stays quiet until the source changes again.

## Resume on re-entry (rule 18)

Read only the current unit's log section and the artifacts it points to, then act on the first step that is not `complete` or `skipped`:

- `in progress` or `blocked`, or an artifact whose `Status` is `draft`: resume that step from the artifact on disk. At a hard gate, re-present the Gate Summary and wait; a `draft` artifact is never treated as approved.
- `pending`, but its artifact is on disk with `Status: approved` (the log lagged): confirm the file, set the step `complete`, and move on.
- `pending` with no artifact: start it normally.

`kit/START.md` detects this state and prints the prompt; a handover (`kit/guides/session-handover.md`) only adds saved context on top of it.

## Project workflow block

`kit/` is git-ignored, so a fresh session sees only the project files. Phase 1 Step 8 and Adopt Step 8 therefore write this section into the project-root `AGENTS.md`, and into `CLAUDE.md` too when the project has one (existing file: show a diff, apply on approval). Substitute the real install directory for `kit/`. Never write a version number into it: `docs/.craft-kit.json` is the one record, so the block cannot go stale.

```markdown
## Workflow (craft-kit)

This project follows the craft-kit workflow. Its files are in `kit/` (git-ignored; if missing, run `npx github:KhoaLy2003/craft-kit#v<kit_version>`, where `<kit_version>` is `kit_version` in `docs/.craft-kit.json`).

- Implement, add, or change a feature, including "implement F12" or "start the next feature": read `kit/phase-2.md` and follow it. Do not write feature code before `docs/specs/<feature-slug>/spec.md` (or `docs/specs/spec.md`) is approved. `docs/` files, including release designs, are inputs to the Spec step, not a substitute.
- Fix a bug: `kit/phase-bug-fix.md`. Decide what to build next: `kit/phase-3-iterate.md`. Unsure: `kit/START.md`.
```
